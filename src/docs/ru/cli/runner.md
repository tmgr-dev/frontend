Раннер — это фоновый процесс, которому принадлежат сессии ваших агентов. `tmgr run` сам запускает его, когда нужно, так что в обычные дни трогать раннер не приходится. Это руководство — про случаи, когда приходится. О первом запуске читайте в уроках [AI-агенты под присмотром](/docs/ru/cli/ai-agents-under-supervision) и [Очередь агентов](/docs/ru/cli/the-agent-queue). Общий обзор — в [руководстве по командной строке](/docs/ru/cli#runner).

Все команды раннера экспериментальные.

## Проверить и запустить раннер {#status}

Чтобы узнать, работает ли раннер, а также его версию, время работы и число сессий:

```sh
tmgr runner status
```

Если раннер старше вашего `tmgr`, в ответе будет подсказка перезапустить его. Если раннер не запущен, команда так и скажет.

Чтобы запустить его вручную:

```sh
tmgr runner start
```

## Остановить и перезапустить {#stop}

Остановка раннера не останавливает агентов. Сессии продолжают работать, и к ним можно вернуться, когда раннер снова запущен. Если вы установили службу входа на Linux, её файл должен быть актуальным — см. заметки о перезапуске ниже.

```sh
tmgr runner stop
```

Чтобы остановить одну сессию, используйте `halt`. См. [Сессии агентов](/docs/ru/cli/sessions#stop).

После обновления `tmgr` перезапустите раннер, чтобы он работал на новой версии. Сессии переживают перезапуск. Если какие-то не вернулись, в выводе будет сказано, сколько.

```sh
tmgr runner restart
```

Что стоит знать:

- Если запущенный раннер новее вашего `tmgr`, перезапуск откажется работать. Запустите более новый `tmgr` или добавьте `--force`, чтобы вернуться к старой версии. Раннер, который не сообщает свою версию, тоже перезапускается только с `--force`.
- На Linux со старым файлом службы systemd завершает все сессии агентов, когда раннер останавливается. Если сессии работают, перезапуск откажется и предложит сначала переустановить службу (следующий раздел). С `--force` перезапуск всё равно выполнится, и systemd может завершить эти сессии. Если сессий нет, команда только предупредит.
- Если работал цикл автопилота, перезапуск его останавливает. Потом запустите его снова.
- Если установлена служба входа, перезапуск идёт через неё.

## Держать раннер включённым после перезагрузки {#service}

Чтобы раннер запускался при входе в систему, сначала посмотрите, что будет установлено. Эта команда ничего не меняет:

```sh
tmgr runner install-service
```

В предпросмотре виден файл службы и команды, которые будут выполнены. На macOS это launchd, на Linux — пользовательский юнит systemd. Если всё в порядке, примените. Нужен терминал, а подтвердить придётся, напечатав фразу:

```sh
tmgr runner install-service --install
```

Та же команда заменяет устаревший файл службы.

На Linux раннер стартует при входе, а не при загрузке системы. Чтобы он стартовал при загрузке без входа, нужен `loginctl enable-linger`; `tmgr` его не запускает.

Если бинарник `tmgr` лежит во временной папке или принадлежит не вам, предпросмотр предупредит об этом. Исправьте это до установки.

Чтобы убрать регистрацию:

```sh
tmgr runner uninstall-service
```

Файл, который создал не `tmgr`, команда не трогает.

## Доверять папке {#trust}

Агенты спрашивают, можно ли им работать в папке. Чтобы не отвечать на этот вопрос для знакомой папки, пометьте её доверенной. Это действует для агентов, запущенных именно в этой папке и в клонах задач, которые `tmgr run` делает из неё. Команда просит подтверждения.

```sh
tmgr runner trust ~/acme-site
```

Без пути берётся текущая папка. Чтобы отозвать доверие и посмотреть, какие папки доверенные сейчас:

```sh
tmgr runner untrust ~/acme-site
tmgr runner trusted
```

В списке для каждой папки указано, как она добавлена и когда.

## Убрать копии завершённых задач {#gc}

Каждая задача, запущенная через `tmgr run <task>` или очередью, работает в своей копии проекта. Когда пулл-реквест слит или закрыт и в копии ничего не запущено, копию можно удалить. Чтобы увидеть, что будет удалено и сколько места освободится, ничего не удаляя:

```sh
tmgr runner gc --dry-run
```

Чтобы удалить копии:

```sh
tmgr runner gc
```

Раннер должен быть запущен: так `gc` узнаёт, какие копии заняты. Сам `gc` раннер не запускает.

Копия остаётся, а в выводе указана причина, если:

- в ней работает агент или другой процесс;
- в ней есть незакоммиченные изменения, неотслеживаемые файлы или игнорируемые файлы, которые не являются результатом сборки;
- в ней есть stash или идёт merge, rebase или похожая операция git;
- HEAD не на ветке задачи;
- её пулл-реквест ещё открыт, пулл-реквеста нет или его состояние не удаётся подтвердить — например, из-за коммитов, которые не были отправлены.

Если какую-то копию удалить не удалось, команда завершается с кодом ошибки.

## Перезапускать тесты при изменении файлов {#watch}

`tmgr attach` умеет открыть панель, которая перезапускает команду — например, тесты — каждый раз, когда меняются файлы в папке. Тот же наблюдатель можно запустить в любом терминале:

```sh
tmgr runner watch --dir . --cmd "cargo test"
```

Он один раз выполняет команду в этой папке, затем проверяет папку примерно каждые полсекунды и запускает команду снова, когда файлы перестают меняться. Папки вроде `.git`, `node_modules`, `target` и `dist` пропускаются. Чтобы остановить, нажмите Ctrl-C.

Этой команды и `runner git-diff` ниже нет во встроенной справке.

## Показать изменения в папке {#git-diff}

`tmgr attach` также умеет показать в панели незакоммиченные изменения в папке сессии. В терминале:

```sh
tmgr runner git-diff --dir .
```

Команда показывает `git diff HEAD` для папки в пейджере: в том, что вы передали через `--pager`, иначе в `delta`, если он установлен, иначе в `less -R`. Программы, указанные в настройках git этой папки, она не запускает. Если эти настройки необычные, команда откажется с сообщением `this folder's git settings are not plain, so the diff is not shown`.

## Вход агентов в изолированных сессиях {#agent-login}

Изолированная сессия работает со своей домашней папкой, поэтому Claude Code в ней не находит ваш обычный вход. Чтобы войти, создайте долгоживущий токен командой `claude setup-token` в обычном терминале, а затем сохраните его для профиля `claude-code`:

```sh
tmgr agents login claude-code
```

Вставьте токен в скрытое поле ввода или передайте его одной строкой через stdin. `tmgr` записывает его в закрытый файл и никогда не печатает. Следующая сессия войдёт с ним. Чтобы заменить сохранённый токен, добавьте `--replace`. Чтобы удалить его:

```sh
tmgr agents logout claude-code
```

Codex может обновить свой вход внутри сессии. Ваш собственный файл входа от этого не меняется. Вместо этого `tmgr agents` и `tmgr run` печатают строку о том, что обновлённый вход ждёт. Чтобы просмотреть и применить его:

```sh
tmgr agents sync codex
```

Команда показывает сводку без значений токенов и применяет вход, только когда вы введёте `apply`. Ей нужен терминал, а внутри сессии агента она не работает. `--discard` отбрасывает ожидающие входы. `--auto on` разрешает раннеру применять их самому после каждой сессии; команда объяснит риск и попросит ввести `I AGREE`. `--auto off` выключает это.

## Следить за изменениями сессий {#events}

Чтобы печатать строку при каждой смене состояния сессии, пока вы не нажмёте Ctrl-C:

```sh
tmgr agents watch
```

С `--json` каждое изменение — один JSON-объект на строку. Чтобы посмотреть, что раннер записал об одной сессии: сколько она работала, ждала и была заблокирована, какой агент, какая ветка и как она завершилась:

```sh
tmgr agents log <session>
```

## Связанные команды {#more}

Облачные воркспейсы и клоны проектов настраиваются в уроке [Очередь агентов](/docs/ru/cli/the-agent-queue). Проверить их потом можно так:

```sh
tmgr runner allowed
tmgr runner list
```

`allowed` показывает облачные воркспейсы, которым разрешено запускать здесь агентов, со сроком действия. `list` показывает репозитории, привязанные к проектам.

Чтобы отменить `runner allow`, запретите воркспейсу запускать здесь агентов. Чтобы отменить `runner bind`, забудьте клон проекта; команда попросит подтверждения:

```sh
tmgr runner disallow <workspace>
tmgr runner unbind <workspace>:<project>
```

Чтобы перенести ветку клона сессии в ваш репозиторий, запустите это внутри репозитория с именем сессии или передайте путь к клону. В самом клоне ничего не запускается.

```sh
tmgr runner import <session>
```
