Раннер — это фоновый процесс, которому принадлежат сессии ваших агентов. `tmgr run` сам запускает его, когда нужно, так что в обычные дни трогать раннер не приходится. Это руководство — про случаи, когда приходится. О первом запуске читайте в уроках [AI-агенты под присмотром](/docs/ru/cli/ai-agents-under-supervision) и [Очередь агентов](/docs/ru/cli/the-agent-queue). Общий обзор — в [руководстве по командной строке](/docs/ru/cli#runner).

Все команды раннера экспериментальные.

## Проверить и запустить раннер {#status}

Чтобы узнать, работает ли раннер, а также его версию, время работы и число сессий:

```sh
tmgr runner status
```

Если раннер старше вашего `tmgr`, в ответе будет подсказка перезапустить его. Если раннер не запущен, команда так и скажет.

Чтобы запустить его вручную:

```sh
tmgr runner start
```

## Остановить и перезапустить {#stop}

Остановка раннера не останавливает агентов. Сессии продолжают работать, и к ним можно вернуться, когда раннер снова запущен.

```sh
tmgr runner stop
```

Чтобы остановить одну сессию, используйте `halt`. См. [Сессии агентов](/docs/ru/cli/sessions#stop).

После обновления `tmgr` перезапустите раннер, чтобы он работал на новой версии. Сессии переживают перезапуск.

```sh
tmgr runner restart
```

Что стоит знать:

- Если запущенный раннер новее вашего `tmgr`, перезапуск откажется работать. Запустите более новый `tmgr` или добавьте `--force`, чтобы вернуться к старой версии.
- Если работал цикл автопилота, перезапуск его останавливает. Потом запустите его снова.
- Если установлена служба входа, перезапуск идёт через неё. Если файл службы устарел, команда посоветует переустановить его (следующий раздел).

## Держать раннер включённым после перезагрузки {#service}

Чтобы раннер запускался при входе в систему, сначала посмотрите, что будет установлено. Эта команда ничего не меняет:

```sh
tmgr runner install-service
```

В предпросмотре виден файл службы и команды, которые будут выполнены. На macOS это launchd, на Linux — пользовательский юнит systemd. Если всё в порядке, примените. Нужен терминал, а подтвердить придётся, напечатав фразу:

```sh
tmgr runner install-service --install
```

На Linux раннер стартует при входе, а не при загрузке системы. Чтобы он стартовал при загрузке без входа, нужен `loginctl enable-linger`; `tmgr` его не запускает.

Если бинарник `tmgr` лежит во временной папке или принадлежит не вам, предпросмотр предупредит об этом. Исправьте это до установки.

Чтобы убрать регистрацию:

```sh
tmgr runner uninstall-service
```

Файл, который создал не `tmgr`, команда не трогает.

## Доверять папке {#trust}

Агенты спрашивают, можно ли им работать в папке. Чтобы не отвечать на этот вопрос для знакомой папки, пометьте её доверенной. Это действует для агентов, запущенных именно в этой папке и в клонах задач, которые `tmgr run` делает из неё. Команда просит подтверждения.

```sh
tmgr runner trust ~/acme-site
```

Без пути берётся текущая папка. Чтобы отозвать доверие и посмотреть, какие папки доверенные сейчас:

```sh
tmgr runner untrust ~/acme-site
tmgr runner trusted
```

В списке для каждой папки указано, как она добавлена и когда.

## Убрать копии завершённых задач {#gc}

Каждая задача, запущенная через `tmgr run <task>` или очередью, работает в своей копии проекта. Когда пулл-реквест слит или закрыт и в копии ничего не запущено, копию можно удалить. Чтобы увидеть, что будет удалено и сколько места освободится, ничего не удаляя:

```sh
tmgr runner gc --dry-run
```

Чтобы удалить копии:

```sh
tmgr runner gc
```

Копии, в которых работает агент или у которых пулл-реквест ещё открыт, остаются. Если какую-то копию удалить не удалось, команда завершается с кодом ошибки.

## Связанные команды {#more}

Облачные воркспейсы и клоны проектов настраиваются в уроке [Очередь агентов](/docs/ru/cli/the-agent-queue). Проверить их потом можно так:

```sh
tmgr runner allowed
tmgr runner list
```

`allowed` показывает облачные воркспейсы, которым разрешено запускать здесь агентов, со сроком действия. `list` показывает репозитории, привязанные к проектам. Отменить можно командами `runner disallow` и `runner unbind`.

Чтобы перенести ветку клона сессии в ваш репозиторий, запустите это внутри репозитория с именем сессии или передайте путь к клону. В самом клоне ничего не запускается.

```sh
tmgr runner import <session>
```
