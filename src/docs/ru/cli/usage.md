`tmgr usage` считает токены и стоимость Claude Code и Codex по их логам на вашем компьютере. Основы показаны в уроке [7. Сколько стоит ИИ](/docs/ru/cli/what-ai-costs-you). Здесь собраны все команды и опции.

Стоимость считается по прейскурантным ценам API за те же токены, это не счёт за подписку. Данные о расходе хранятся на вашем компьютере, за последние 90 дней.

## Чтение логов {#consent}

`tmgr` читает логи только с вашего согласия. Посмотреть текущий выбор, разрешить или запретить:

```sh
tmgr usage consent
tmgr usage consent allow
tmgr usage consent deny
```

- Пока вы не выбрали, логи читают команды, которые вы запускаете вручную. Десктопное приложение TMGR и фоновая работа (автопилот, автоматическая загрузка после запуска агента) ждут `allow`.
- После `deny` логи не читает никто. Команды показывают данные, сохранённые раньше. Раннер агентов тоже перестаёт читать логи сессий.
- Что сохраняется: количества, токены, стоимость, названия моделей, время, id сессий, папки проектов и ветки, названия использованных инструментов, навыков и команд, типы изменённых файлов и пул-реквесты. Текст промптов и ответов не сохраняется никогда.
- Ничто не покидает ваш компьютер, пока вы сами не загрузите данные командой [`tmgr usage sync`](#sync).

Выбор общий с десктопным приложением TMGR.

## Сводка {#summary}

Без опций команда показывает три периода: сегодня, последние 7 дней и последние 30 дней.

```sh
tmgr usage
```

Можно выбрать один период:

- `--today` или `--yesterday`.
- `--week`: последние 7 дней, включая сегодня.
- `--month`: последние 30 дней, включая сегодня.
- `--since` и `--until`: дни в формате `YYYY-MM-DD`, в вашем часовом поясе. День `--until` входит в период, и без `--since` эта опция не работает.

Сгруппировать строки можно опцией `--by`: `tool`, `model`, `account`, `project`, `branch`, `day` или `task`. Отфильтровать — опциями `--task`, `--tool claude` или `--tool codex` и `--account` с меткой аккаунта.

```sh
tmgr usage --since 2026-10-01 --until 2026-10-31 --by project
tmgr usage --week --tool codex --by model
```

Каждая команда usage сначала читает новые строки логов. Добавьте `--no-scan`, чтобы пропустить это и сразу показать сохранённые данные.

## Лимиты {#limits}

```sh
tmgr usage limits
```

Каждая строка — окно лимита: инструмент, аккаунт, окно (сессия, неделя или неделя для одной модели), сколько процентов израсходовано, сколько осталось до сброса, откуда взято число и насколько оно свежее.

Лимиты Codex берутся из логов его сессий. Для лимитов Claude Code нужен хук строки состояния: см. [Строка состояния Claude Code](#statusline). Без него команда предупреждает, что лимитов Claude нет.

## Одна задача {#task}

```sh
tmgr usage task TM-123
```

Команда показывает, сколько агенты работали над задачей, стоимость, токены (входные, чтение и запись кэша, выходные, рассуждения), какую часть лимитов это заняло, а также инструменты, навыки, плагины, MCP-серверы и хуки, которыми пользовались агенты.

- `--tree` показывает всех агентов, а не только верхний уровень.
- `--days` задаёт, на сколько дней назад смотреть: по умолчанию 30, не больше 90.

Расход привязывается к задаче через запуски агентов, например через `tmgr run` или `tmgr agent start`. Расход вне запуска виден без задачи в `tmgr usage --by task`.

## Прочитать логи {#scan}

```sh
tmgr usage scan
```

Команда читает новые строки логов в данные о расходе и пишет, сколько файлов и событий прочитано. Остальные команды делают это сами. Первое чтение больших логов может занять минуту.

## Аккаунты {#accounts}

Аккаунт — это одна папка настроек Claude Code или Codex. По умолчанию `tmgr` читает `~/.claude` и `~/.codex` (метки `claude` и `codex`), а также папки из `CLAUDE_CONFIG_DIR` и `CODEX_HOME`, если эти переменные заданы.

Чтобы читать другую папку, например второй вход в Claude, добавьте её под меткой:

```sh
tmgr usage accounts
tmgr usage accounts add --tool claude --root ~/.claude-work --label work
tmgr usage accounts remove work
```

Первая команда показывает аккаунты и откуда взялся каждый. Папка должна существовать. `remove` работает только для добавленных вами аккаунтов, а уже сохранённый расход остаётся.

## Цены {#pricing}

```sh
tmgr usage pricing
tmgr usage pricing show --model opus
```

Первая команда говорит, какой прейскурант используется и сколько в нём моделей. С `--model` она показывает цены за миллион токенов для моделей, в названии которых есть этот текст.

`tmgr` поставляется со своим прейскурантом. Чтобы скачать актуальный публичный прейскурант LiteLLM и пересчитать всё сохранённое:

```sh
tmgr usage pricing update
```

`--offline` возвращает прейскурант, который поставляется с `tmgr`. Если цена модели неизвестна, её события не входят в стоимость, и вы видите предупреждение.

## Загрузка в TMGR {#sync}

Загрузка показывает участникам рабочего пространства задачи, во сколько обошлись агенты на этой задаче. По каждой задаче отправляется одна сводка: стоимость, токены, время, дерево агентов, названия инструментов и навыков. Промпты, ответы, пути к файлам и аргументы команд не отправляются никогда. Локальные рабочие пространства не загружаются никогда.

Ничего не загружается, пока не включено и то и другое:

1. В терминале выполните `tmgr usage sync on`. Команда покажет, кто увидит данные, и настоящий пример, а затем попросит ввести `yes`.
2. В разделе [Настройки → Работа агента](/settings?tab=agent-work) включите **Синхронизация использования агентов**.

После этого загружайте вручную:

```sh
tmgr usage sync --dry-run
tmgr usage sync
tmgr usage sync --task TM-123
```

`--dry-run` печатает, что было бы отправлено, и ничего не отправляет; работает и до включения загрузки. `--days` задаёт, на сколько дней назад читать (по умолчанию 30, не больше 90). `--force` вместе с `--task` отправляет данные, даже если расход на этом компьютере меньше уже загруженного.

Чтобы загружать автоматически после каждого запуска агента:

```sh
tmgr usage sync auto on
tmgr usage sync auto status
tmgr usage sync auto off
```

`auto on` показывает, что будет отправляться, и просит отдельного подтверждения. Без терминала подтвердите опцией `--yes-auto`. `tmgr usage sync on --yes-auto` включает сразу и загрузку, и автоматическую загрузку.

Проверить и остановить:

```sh
tmgr usage sync status
tmgr usage sync off
tmgr usage sync forget
```

`status` говорит, включена ли загрузка и чем закончился последний запуск. `off` останавливает загрузку; то, что вы загрузили раньше, остаётся на сервере. `forget` удаляет ваши загрузки с сервера — все или по одной задаче с `--task`. Команда просит ввести подтверждение или принимает `--yes`. Если выключить **Синхронизация использования агентов** в настройках, всё загруженное тоже удаляется.

## Сброс {#reset}

```sh
tmgr usage reset
```

Команда удаляет все сохранённые данные о расходе и сохранённые вопросы раннера агентов. Логи Claude Code и Codex остаются. Сначала команда спрашивает подтверждение. Выбор о согласии не меняется.

Если вы загружаете расход, выполните `tmgr usage sync forget` до `reset`. Иначе более поздняя и меньшая загрузка может заменить полную на сервере.

## Строка состояния Claude Code {#statusline}

`tmgr` получает лимиты Claude Code через строку состояния Claude Code. Он добавляет туда свою команду, чтобы `tmgr usage limits` мог показать лимиты Claude.

```sh
tmgr usage statusline install
```

Команда печатает изменение в `settings.json` Claude Code и ничего не меняет. Чтобы записать его:

```sh
tmgr usage statusline install --install
```

Команда показывает изменение, просит подтвердить в терминале и сохраняет резервную копию файла. `--yes` она не принимает никогда. Если у вас уже есть команда строки состояния, она продолжает работать: `tmgr` запускает её и выводит то, что она печатает.

`--account` выбирает другой аккаунт Claude по метке (по умолчанию `claude`). Чтобы вернуть прежнюю команду строки состояния:

```sh
tmgr usage statusline uninstall
```
