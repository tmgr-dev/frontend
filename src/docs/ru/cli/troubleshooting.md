Каждый раздел ниже — это проблема и её решение. Про установку и первый вход читайте в уроке [«Установка и вход»](/docs/ru/cli/install-and-sign-in), а полный список команд — в [руководстве по командной строке](/docs/ru/cli).

## Обновление tmgr {#update}

Проверить, есть ли новый релиз, не устанавливая его:

```sh
tmgr self-update --check
```

Установить:

```sh
tmgr self-update
```

Прежняя программа остаётся рядом с новой под именем `tmgr.old`. Флаг `--channel beta` берёт бета-канал вместо стабильного.

### «no stable release found» {#no-release}

На стабильном канале пока ничего не опубликовано. В подсказке предлагается `--channel beta`.

### «tmgr is managed by ...» {#managed}

Вы поставили `tmgr` через менеджер пакетов, и самообновление с ним бы конфликтовало. Обновитесь командой, которую печатает сообщение.

### «no permission to write the install directory» {#permission}

`tmgr` никогда не использует `sudo`. Переустановите программу в папку, которой вы владеете, скриптом установки из урока [«Установка и вход»](/docs/ru/cli/install-and-sign-in).

### «refusing to downgrade» {#downgrade}

Этот релиз старше того, которому эта машина уже доверяла. Если он действительно нужен, выполните в терминале `tmgr self-update --allow-downgrade`. Команда попросит подтверждение.

## Не проходит проверка подписи {#signature}

`tmgr self-update` ставит только подписанные релизы. Сначала он проверяет подпись манифеста релиза, затем контрольную сумму скачанного архива и только после этого заменяет программу. Если любая проверка не прошла, ничего не устанавливается, а ваш текущий `tmgr` продолжает работать. Типичные сообщения:

- `the manifest signature does not verify; refusing to update` или `the release is not signed`: не обходите проверку. Повторите позже, а если ошибка остаётся, переустановите `tmgr` скриптом установки.
- `the archive does not match the signed checksum; nothing was installed`: загрузка повреждена или подменена. Запустите обновление ещё раз.
- `the manifest has expired; refusing a stale release`: релиз слишком старый, чтобы ему доверять. Дождитесь нового или переустановите `tmgr`.
- `this build has no update key; install a signed release`: эта копия собрана не из официального релиза. Переустановите её скриптом установки.

## Где хранится ваш вход {#credentials}

`tmgr` сохраняет токен в хранилище учётных данных операционной системы (связке ключей). Токен никогда не печатается.

Если хранилища нет (например, на сервере без рабочего стола), `tmgr login` сохранит токен в приватный файл с правами 0600 и сообщит, где он лежит.

### «the OS credential store refused access» {#keychain-locked}

Связка ключей заблокирована, или в доступе отказано. Разблокируйте её и повторите. Если воспользоваться ею нельзя, переключитесь на приватный файл для следующих команд:

```sh
TMGR_CREDENTIAL_STORE=file tmgr login
```

Чтобы все последующие команды тоже брали токен из файла, добавьте `TMGR_CREDENTIAL_STORE=file` в профиль оболочки.

### Ошибка файла с учётными данными {#file-mode}

Если файл доступен другим пользователям, `tmgr` откажется его читать и подскажет команду с `chmod 600`. Выполните её. Если файл повреждён, удалите его и войдите заново.

## Войти заново {#re-login}

Сообщения `not logged in or the session expired`, `session expired or revoked` и `stored token is malformed` значат, что токен больше не работает. Войдите заново:

```sh
tmgr login
```

Чтобы начать с чистого листа, сначала выйдите. Локальный токен будет удалён:

```sh
tmgr logout
```

Кто сейчас вошёл, покажет `tmgr whoami`. Если браузер не открывается, добавьте `--no-browser`. Если код входа истёк, снова выполните `tmgr login`.

## «this login does not allow that» {#scopes}

Дальше в сообщении идёт `(needs scope ...)`. Ваш вход сделан без этого права. В подсказке напечатана готовая команда `tmgr login --scopes ...` с недостающим правом. Выполните её и подтвердите запрос в браузере.

То же относится к ошибкам со словом `agent-approvals:write`: оно нужно автопилоту, чтобы подписывать задачи. См. [Автопилот](/docs/ru/cli/autopilot).

## Копирование в tmgr attach по SSH не работает {#clipboard}

Терминал должен разрешать программам писать в буфер обмена (OSC 52). Выполните это на своём компьютере, а не на сервере:

```sh
tmgr setup terminal
```

Перед любой записью команда покажет каждое изменение и спросит `Apply this change? [y/N]`. Если в выводе сказано перезапустить терминал или перечитать его настройки, сделайте это. Чтобы только посмотреть, что изменится, добавьте `--check`.

## Ошибки сервера {#server}

- `server unavailable (HTTP 502)` и похожие: сервер или ваше соединение недоступны. Повторите через минуту.
- `rate limited by the server`: подождите минуту.
