Здесь описаны команды `tmgr`, которые [руководство по командной строке](/docs/ru/cli) только называет. Каждая команда принимает и `--json`, чтобы вывод могли читать скрипты.

## Настройки {#config}

`tmgr` хранит настройки в файле `config.toml` в папке `~/.config/tmgr` или в `$XDG_CONFIG_HOME/tmgr`, если эта переменная задана.

```sh
tmgr config list
tmgr config get branch_template
tmgr config set review_status "Code review"
tmgr config path
```

`list` печатает все настройки, `get` — одну, `set` меняет одну, `path` печатает, где лежит файл. Неизвестный ключ или неверное значение отклоняются, и в ошибке перечислены ключи, которые можно менять.

| Ключ | Что задаёт |
| --- | --- |
| `server` | Сервер API TMGR. По умолчанию `https://api.tmgr.dev`. |
| `web_url` | Адрес веб-приложения для ссылок на задачи. |
| `default_workspace` | Рабочее пространство, когда вы не указываете `--ws`. Его задаёт `tmgr ws use`. Можно указать `local:<code>`. |
| `branch_template` | Имя ветки, которую создаёт `tmgr start`. По умолчанию `{key_lower}-{slug}`. Подстановки: `{key}`, `{key_lower}`, `{code_lower}`, `{seq}` и `{slug}` (заголовок задачи). |
| `review_status` | Статус, в который `tmgr done` переводит задачу. По умолчанию `Review`. |
| `upload_status` | `true` разрешает `tmgr agent status set` отправлять состояние сессий. По умолчанию выключено. См. [Сессии агентов](#agent-status). |
| `hook_git_commits` | `false` запрещает хуку Claude Code добавлять в запуск агента коммиты, сделанные во время запуска. По умолчанию включено. |
| `local_user_id` | Id пользователя, от имени которого `tmgr` работает в локальных пространствах десктопного приложения. `-1` — локальный аккаунт десктопа. |

Ключи `attach.*` настраивают `tmgr attach`, это экспериментальная команда:

| Ключ | Значения |
| --- | --- |
| `attach.sidebar_width` | Ширина боковой панели, от 16 до 60 колонок. |
| `attach.theme` | `auto`, `dark`, `light` или `high-contrast`. |
| `attach.signal.permission`, `attach.signal.question`, `attach.signal.input` | `true` или `false`: звуковой сигнал и подсветка, когда сессия ждёт разрешения, ответа на вопрос или ввода. |
| `attach.signal.quiet` | Часы без сигналов, например `22:00-08:00`, или `off`. |
| `attach.prompt.send` | `true` отправляет сохранённый промпт, а не только вставляет его. |
| `attach.summary` | `ask`, `always` или `never`: итог сессии Claude, который записывается в её задачу, когда сессия заканчивается. |
| `attach.push.long` | Минуты или `off`: пуш на телефон, когда заканчивается ход, который шёл столько времени. |
| `attach.push.error` | `true` или `false`: пуш, когда сессия завершилась с ошибкой. |
| `attach.push.blocked` | Минуты или `off`: пуш, когда запрос разрешения или вопрос ждёт столько времени. |
| `attach.push.quiet` | Часы без пушей, например `22:00-08:00`, или `off`. |
| `attach.push.debounce` | Минуты: не больше одного пуша одного вида на сессию за это время. |
| `attach.copy.clean` | `false` копирует текст как есть, без очистки. |
| `attach.worktree` | `false` запускает сессии агентов на месте, а не в отдельной копии репозитория. |
| `attach.checkpoints` | `true` сохраняет папку сессии после каждого хода, для новых сессий. |
| `attach.checkpoints_keep` | Сколько контрольных точек хранит сессия, от 3 до 1000. |
| `attach.permission_cards` | `true` позволяет отвечать на запросы разрешений агента из боковой панели. |

## Как указать задачу {#refs}

```sh
tmgr refs
```

Команда печатает, как указать задачу в любой команде:

- `TM-512`: код проекта (категории) и номер, как в заголовке задачи. Нужен `--ws` или рабочее пространство по умолчанию.
- `#8974` или `8974`: глобальный id задачи.

Всё остальное отклоняется ещё до отправки запроса.

## Папки проектов {#project}

Скажите `tmgr`, в какой папке лежит код проекта. Тогда `tmgr start TM-123` создаёт ветку в этом репозитории, где бы вы ни запускали команду, а запуски агентов по задачам проекта знают, где код.

```sh
tmgr project map TM ~/src/tmgr
tmgr project list
tmgr project unmap TM
```

`map` предупреждает, если папка не git-репозиторий. `list` помечает папки, которых больше нет, как пропавшие.

## Рутины {#routines}

```sh
tmgr routine list
tmgr routine list --date 2026-11-10
tmgr routine list --json
tmgr routine done 42
```

`list` показывает рутины на сегодня или на день из `--date` и отмечает выполненные. Id есть только в выводе `--json`, в поле `id`. `done` отмечает рутину выполненной на сегодня. С `--date` — на другой день, но только если у рутины уже есть повторение в этот день. Рутины в приложении: [Рутины](/docs/ru/app/routines).

## Заметки, день и журнал запусков {#day}

- `tmgr note` пишет страницу в вашем редакторе. См. [Страницы и карта → Из терминала](/docs/ru/app/pages#cli).
- `tmgr today` показывает учтённое время, время агентов и рутины за день. `--yesterday` или `--date` выбирает другой день; `--mine` считает только запуски агентов, которые начали вы. См. [Рабочий цикл start → done](/docs/ru/cli/the-start-done-cycle#t-today).
- `tmgr log` показывает запуски агентов. Сузить список можно опциями `--task`, `--agent` и `--since` (например `2h` или `1d`), размер задаёт `--limit`, а `--follow` обновляет список на ходу. См. [Отчёты агентов о работе](/docs/ru/cli/agent-work-reports#t-log).

```sh
tmgr today --yesterday --mine
tmgr log --agent codex --since 1d
```

## Сессии агентов {#agent-status}

Сессии агентов могут сообщать рабочему пространству своё состояние: над какой задачей работают и работают ли, ждут или заблокированы. Пока вы это не включите, ничего не отправляется:

```sh
tmgr config set upload_status true
```

После этого каждое обновление отправляет задачу, состояние, профиль агента, время и имя хоста этого компьютера. Содержимое терминала не отправляется никогда.

```sh
tmgr agent status set my-session-01 --state working --task TM-123
tmgr agent status list
tmgr agent status clear my-session-01
```

Id сессии вы выбираете сами: от 8 до 64 символов из букв, цифр, `_` и `-`. Состояние: `working`, `waiting`, `blocked`, `idle`, `done` или `exited`. `--profile` называет агента (по умолчанию `claude-code`). `list` показывает сессии рабочего пространства и помечает старые как устаревшие (stale). `clear` закрывает сессию. Если работа агентов в рабочем пространстве выключена, ничего не записывается.

## Подтвердить локальную задачу для агентов {#task-confirm}

В локальном рабочем пространстве десктопного приложения [очередь агентов](/docs/ru/cli/queue) по умолчанию запускает только задачи, текст которых написал человек. Если задачу изменил агент или плагин, прочитайте её и подтвердите:

```sh
tmgr --ws local:my-notes task confirm TM-12
```

Команда показывает всё, что прочитает агент: заголовок, описание, контрольные точки и комментарии. Чтобы подтвердить, введите первые 12 символов снимка, который она напечатает. Команда работает только в терминале, никогда внутри сессии агента и только для локальных пространств. Если задача за это время изменилась, ничего не подтверждается.

## Ответы, которые агенты ещё не забрали {#pending-delivery}

```sh
tmgr decisions pending-delivery
```

Команда показывает ответы из входящих решений (Decisions), которые ещё не забрал ни один агент, от старых к новым: когда вы ответили, id карточки, состояние доставки, задачу и заголовок. Нужно десктопное приложение TMGR. См. [Входящие решения](/docs/ru/cli/the-decisions-inbox).

## Версия и обновления {#version}

```sh
tmgr version
tmgr self-update
```

`version` печатает версию, коммит и платформу сборки. Обновления и их ошибки описаны в разделе [Решение проблем → Обновление tmgr](/docs/ru/cli/troubleshooting#update).

`tmgr setup terminal` разрешает программам в терминале писать в буфер обмена, чтобы копирование в `tmgr attach` работало по SSH. См. [Решение проблем](/docs/ru/cli/troubleshooting#clipboard).

## Хуки git и агентов {#hooks}

`tmgr git install-hooks` добавляет хук коммита в текущий репозиторий: он дописывает к каждому коммиту строку Refs с задачей текущей ветки. См. [Рабочий цикл start → done](/docs/ru/cli/the-start-done-cycle#t-commit).

Чтобы добавить его во все репозитории на этом компьютере:

```sh
tmgr git install-hooks --global
```

Команда задаёт в глобальном конфиге git одну папку хуков для всех репозиториев (`core.hooksPath`) и сначала спрашивает. Остальные хуки из собственной папки хуков репозитория после этого не запускаются; его хук commit-msg по-прежнему работает. Хук commit-msg, который уже лежит в общей папке, сохраняется и запускается первым.

Чтобы убрать хуки, которые `tmgr hook install` добавил в Claude Code, Codex или входящие решения:

```sh
tmgr hook uninstall claude
tmgr hook uninstall codex --print
```

Команда убирает только записи `tmgr`, показывает изменение, сначала спрашивает и сохраняет резервную копию. `--print` только показывает изменение. `--project` меняет `.claude/settings.json` текущего репозитория, а не ваши пользовательские настройки.
