Очередь агентов запускает агентов на вашей машине для задач, которые разрешает правило и которые вы одобрили. Первая настройка — от веб-приложения до первого пулл-реквеста — описана в уроке [Очередь агентов](/docs/ru/cli/the-agent-queue). Это руководство — о повседневной работе с очередью.

`tmgr queue` — экспериментальная команда, во встроенной справке её нет. `tmgr queue autopilot` — то же самое, что `tmgr autopilot`; см. [Автопилот](/docs/ru/cli/autopilot).

## Проверить очередь {#status}

```sh
tmgr queue status
```

В выводе видно, включена ли очередь и стоит ли она на паузе, состояние фонового цикла, правила и открытые взятые задачи (pickup). Pickup — это одна задача, которую взяла очередь: в каждой строке её id, правило, задача, статус и начало хеша её пакета. В конце — запрошенные и работающие команды.

Чтобы следить дальше, добавьте `--tail`. Команда напечатает сводку, а затем каждое новое событие фонового цикла, пока вы не нажмёте Ctrl+C:

```sh
tmgr queue status --tail
```

Если `queue.toml` изменили не через `tmgr queue`, статус предупредит об этом, и очередь не будет работать, пока вы не подтвердите файл командой `tmgr queue enable`.

## Пауза и продолжение {#pause}

Пауза сразу прекращает брать новую работу. Уже работающие агенты продолжают.

```sh
tmgr queue pause
tmgr queue resume
```

`resume` запускайте сами в обычном терминале: внутри сессии агента команда отклоняется.

## Включить и выключить очередь {#enable}

```sh
tmgr queue enable
```

`enable` показывает риски и ваши правила и просит ввести `I AGREE`. Нужен терминал. После этого очередь сама работает в фоне через раннер.

```sh
tmgr queue disable
```

`disable` выключает очередь: ничего нового не стартует, фоновый цикл завершается. Выключить очередь можно всегда, даже если файл её правил изменили не через `tmgr queue`.

## Правила {#rules}

Правило решает, что может стартовать: воркспейс, проект, персона, профиль агента, папка и сколько агентов одновременно. Как добавить первое правило, показано в [уроке](/docs/ru/cli/the-agent-queue#t-rule). При добавлении правила нужно ввести `I AGREE`.

Чтобы вывести правила или удалить одно по имени:

```sh
tmgr queue rules list
tmgr queue rules rm my-site
```

Другие параметры `tmgr queue rules add`:

- `--status-type`: Брать задачи с типом статуса `backlog` (по умолчанию) или `active`
- `--hours`: Рабочие часы по местному времени, например `09-19`
- `--max-concurrent`: Сколько агентов правила одновременно, от 1 до 3 (по умолчанию 1)
- `--trusted-author`: `human` (по умолчанию), `agent` или `unrecorded`; для нескольких повторите флаг
- `--auto`: Запускать, не спрашивая про каждую задачу; только для задач от авторов-людей
- `--mode`: Режим разрешений облачного правила: `ask`, `accept-edits`, `plan` или `bypass`
- `--model`: Модель, которую получит профиль агента

## Одобрить задачу {#approve}

В локальном воркспейсе правило без `--auto` ждёт вас перед каждой задачей. `tmgr queue status` показывает такую задачу со статусом `pending_approval`. Чтобы одобрить её:

```sh
tmgr queue approve <pickup>
```

Команда постранично показывает, что именно стартует, и просит ввести первые 12 символов хеша пакета. Нужен терминал. Задачу облачного воркспейса одобряет подпись владельца в веб-приложении, а не эта команда.

## Освободить зависшую задачу {#release}

Если очередь не может понять, удался ли старт, задача показывает `unknown_start` и держит своё место. Сначала проверьте через `tmgr agents`, что агент этой задачи не работает. Затем освободите место:

```sh
tmgr queue release <pickup>
```

Для подтверждения введите id pickup из `tmgr queue status`, а не ключ задачи. Pickup завершится как неудачный.

## Запросить команду {#team}

Чтобы над одной задачей работала команда — ведущий и от 1 до 5 исполнителей:

```sh
tmgr queue add TM-12 --team 2 --mode heavy
```

`--team` обязателен. `--mode` — это `eco` (ведущий Sonnet, исполнители Haiku, по умолчанию) или `heavy` (ведущий Opus, исполнители Sonnet). Задаче должно подходить правило с профилем `claude-code`. Команда покажет сводку и попросит ввести `TEAM`. Команда агентов стартует, когда правило разрешит задачу, со всеми проверками правила.

## Один проход сейчас {#run-once}

Чтобы очередь поискала работу прямо сейчас, не дожидаясь фонового цикла:

```sh
tmgr queue run-once
```

Команда напечатает, что произошло с каждой задачей, или `Nothing to do.`, `Queue is off.` или `Queue is paused.`.
