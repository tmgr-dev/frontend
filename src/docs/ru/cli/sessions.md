`tmgr run` запускает агента и создаёт сессию. Это руководство — о том, что делать с сессией дальше. Первый запуск описан в уроке [AI-агенты под присмотром](/docs/ru/cli/ai-agents-under-supervision). О процессе, который стоит за сессиями, читайте в [Обслуживании раннера](/docs/ru/cli/runner). Общий обзор — в [руководстве по командной строке](/docs/ru/cli#runner).

Все эти команды экспериментальные. Везде, где команда принимает сессию, можно указать её id или имя.

## Посмотреть сессии {#list}

Чтобы вывести сессии вместе с состоянием:

```sh
tmgr agents
```

В каждой строке — имя, состояние, id, команда и папка. Состояние бывает `starting`, `working`, `waiting` (агент ждёт вас), `blocked` (ему нужно решение), `exited` или `failed`. Под таблицей — итоговая строка со счётчиками.

Чтобы вывести то, что сессия показывает прямо сейчас, простым текстом (с `--lines` — больше истории):

```sh
tmgr peek <session> --lines 100
```

Чтобы открыть живой полноэкранный вид; без указания сессии берётся самая новая из запущенных:

```sh
tmgr attach
```

## Переименовать сессию {#rename}

Id не меняется. Новое имя должно быть уникальным среди ваших сессий.

```sh
tmgr rename <session> review-footer
```

## Написать в сессию {#send}

Чтобы напечатать строку в сессии и нажать Enter:

```sh
tmgr send <session> "Run the tests and fix what fails"
```

С флагом `--no-enter` текст печатается без нажатия Enter. Чтобы дождаться ответа и вывести, что появилось на экране, добавьте `--wait idle` (пока агент снова не начнёт ждать или не окажется заблокирован) или `--wait exit` (пока сессия не завершится). `--timeout` ограничивает ожидание, по умолчанию 10 минут.

```sh
tmgr send <session> "Summarize your changes" --wait idle --timeout 5m
```

При `--wait idle` код выхода равен 8, если агент оказался заблокирован. Это удобно в скриптах. Состояние определяется по экрану, поэтому агент может выглядеть свободным, когда это не так.

## Остановить и удалить сессию {#stop}

`halt` останавливает одну сессию: сначала прерывает агента, а если не помогло — завершает. Остановка раннера этого не делает: когда раннер остановлен, сессии продолжают работать.

```sh
tmgr halt <session>
```

Если агент не останавливается, добавьте `--kill`, чтобы завершить его сразу. Для уже завершившейся сессии `--kill` также останавливает оставшиеся от неё фоновые процессы.

Чтобы удалить завершившуюся сессию:

```sh
tmgr rm <session>
```

Если сессия работала в своей копии проекта (следующий раздел), `rm` предложит удалить и копию, но только если она чистая: без незакоммиченных и неотслеживаемых изменений и без незавершённой операции git. Если в копии есть новые коммиты, её ветка остаётся в репозитории. Если копия не чистая, `rm` оставит её и скажет почему.

## Своя копия проекта у сессии {#copy}

Изолированная сессия, которую вы запускаете с `--agent` в git-репозитории, по умолчанию работает в своей копии проекта: это checkout в `<repo>-worktrees/<session name>` на новой ветке с тем же именем. Так два агента никогда не пишут в одни и те же файлы.

Сессия стартует прямо в папке, если добавить `--no-worktree`, `--trust` или `--no-sandbox`. Чтобы выключить копию для всех сессий, задайте `attach.worktree` значение `false` командой `tmgr config set`.

## Запустить завершённую сессию снова {#resume}

`resume` запускает завершённую сессию на месте и продолжает разговор с агентом. Команда показывает, что собирается сделать, и просит подтвердить.

```sh
tmgr resume <session>
```

После обычного `resume` в выводе будет команда, чтобы открыть сессию; живой вид сам не открывается. Команда принимает и id разговора с агентом, который запускали не через `tmgr`. Чтобы продолжить в новой сессии, не трогая исходный разговор, добавьте `--fork`. `--mode` задаёт режим разрешений. С `--fork`, `--mode`, `--no-sandbox` или id разговора живой вид открывается сразу; чтобы его не открывать, добавьте `--no-attach`.

Если сессии остановила перезагрузка или выход из системы, эта команда покажет их и предложит запустить снова, по одному подтверждению на каждую:

```sh
tmgr agents restore
```

## Найти прошлые разговоры {#find}

Чтобы вывести прошлые сессии — и сессии `tmgr`, и сессии Claude Code и Codex на этой машине:

```sh
tmgr session list --agent claude --limit 20
```

`--agent` принимает `claude` или `codex`. Лимит по умолчанию — 50. Чтобы найти сессии по тому, что в них говорилось, используйте поиск. При первом поиске строится локальный индекс ваших расшифровок. Ничего не покидает ваш компьютер.

```sh
tmgr session list --search "footer layout"
```

## Сводка и экспорт расшифровки {#transcripts}

Сводка и экспорт работают только для сессий, которые запустил `tmgr`, — тех, что показывает `tmgr agents`. Для разговора, который виден только в `session list`, они ответят `no session matches`. Кроме того, они работают только для сессий Claude Code: для сессий Codex они ответят, что недоступны. Список и поиск охватывают оба агента.

Чтение расшифровок требует вашего согласия. Если оно выключено, команда подскажет, как его включить.

Чтобы вывести короткую сводку того, что сделала сессия:

```sh
tmgr session summary <session>
```

Текст пишет модель. С флагом `--plain` вы получите только файлы, коммиты и пулл-реквесты, и модель не вызывается.

Чтобы сохранить сессию в Markdown-файл или страницей в текущем воркспейсе:

```sh
tmgr session export <session> --md notes.md
tmgr session export <session> --page
```

Перед записью `tmgr` проверяет расшифровку на секреты и даёт вам просмотреть каждую находку. `--remove-findings` убирает их без вопросов. Файл доступен только вам и не перезаписывается без подтверждения. С `--page` текст уходит на сервер TMGR, поэтому для подтверждения нужно ввести код воркспейса. Без `--md` и `--page` ничего не записывается.

## Время в attach {#time}

`tmgr attach` считает время, которое вы проводите с каждой сессией. Пока окно attach перед вами и сессия в фокусе, её время идёт: пока вы печатаете — как ввод, остальное — как чтение. После паузы длиннее порога простоя время перестаёт идти. По умолчанию порог — 2 минуты.

Чтобы посмотреть итоги:

```sh
tmgr time --today
```

В каждой строке — сессия, её папка, задача, общее время, ввод и чтение и состояние отправки. `--since` принимает дату (`YYYY-MM-DD`) или срок вроде `12h` или `7d`. `--by` группирует строки по `session` (по умолчанию), `folder` или `task`.

Время сессии, которая относится к задаче, — например, запущенной через `tmgr run <task>`, — отправляется в эту задачу и добавляется к её учтённому времени. Время, которое уже покрыто таймером задачи, второй раз не считается. Для отправки нужен модуль **Session time → task** в [Настройки → Модули](/settings/modules). По умолчанию он выключен, а включить его может только владелец воркспейса. Без него в строках будет `skipped`. Время с отметкой `skipped` — когда модуль или отправка были выключены — позже не отправляется. Время локального воркспейса остаётся на вашем компьютере, в строках будет `local`.

Отправка включена по умолчанию. Чтобы проверить её, выключить или включить:

```sh
tmgr time sync
tmgr time sync off
```

Чтобы изменить порог простоя, укажите его в секундах, от 30 до 3600:

```sh
tmgr time idle 300
```

## Вопросы, которые задали агенты {#questions}

`tmgr attach` читает расшифровки сессий Claude Code и Codex и ведёт список вопросов, которые вам задали агенты. Чтобы вывести открытые:

```sh
tmgr questions
```

В каждой строке — id вопроса, сессия, когда он задан, и сам вопрос. `--session` оставляет в списке одну сессию. `--status` принимает `open` (по умолчанию), `answered`, `ignored` или `all`.

Чтение расшифровок требует вашего согласия. Если оно выключено, в конце списка будет строка о том, как его включить.

Если вы ответили в сессии сами, отметьте вопрос как отвеченный. Чтобы убрать вопрос из открытых, пропустите его. Id нужен хотя бы из 4 символов:

```sh
tmgr questions answer <id>
tmgr questions ignore <id>
```

Чтобы отличать настоящие вопросы от риторических, `tmgr` отправляет текст сообщений агента, похожих на вопрос, вашей собственной команде `claude` с моделью Haiku. По умолчанию это включено. Выключите, чтобы искать вопросы только по встроенным правилам и ничего никуда не отправлять:

```sh
tmgr questions haiku off
```

Без `on` или `off` команда показывает текущую настройку.
