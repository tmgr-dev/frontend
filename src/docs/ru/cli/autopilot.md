Автопилот берёт задачи воркспейса и запускает на них команды агентов через очередь агентов. Каждая задача заканчивается пулл-реквестом, сам автопилот ничего не вливает. Если вы ещё не настроили очередь, начните с урока [«Очередь агентов»](/docs/ru/cli/the-agent-queue). Краткое описание есть в [руководстве по командной строке](/docs/ru/cli#autopilot).

## Что он делает {#what}

Автопилот читает бэклог, показывает список задач, которые можно запустить, и просит один раз подтвердить. Дальше он работает в фоне на вашей машине:

- Подписывает одобрение выбранных задач ключом этого компьютера, так что подтверждать каждую по отдельности не нужно.
- Запускает агентов в пределах заданного числа команд и не больше, чем разрешает правило очереди.
- Включает очередь на время работы. Когда вы останавливаете автопилот, очередь выключается.

Нужно правило очереди для облачного воркспейса. Без него команда остановится с ошибкой `autopilot needs a rule for a cloud workspace`: добавьте правило, как показано в уроке про очередь.

## Запуск {#start}

Начните с нужных лимитов:

```sh
tmgr autopilot start --max-teams 2 --max-hours 4
```

`start` берёт единственное облачное правило или то, что вы выберете флагом `--rule NAME`. Если облачных правил несколько, он перечислит их и спросит `Which rule?`; нажмите Enter, чтобы взять то, которым пользовались в прошлый раз. Чтобы указать воркспейс, напишите `tmgr autopilot <workspace>` с теми же флагами. Автопилот задаёт вопросы настройки, печатает сводку по задачам, подписи, лимитам и правилу и ждёт. Чтобы подтвердить, введите текст, который он покажет: код воркспейса и число задач. Флаги, которые вы передали, пропускают соответствующие вопросы. Чтобы задать вопросы заново, добавьте `--setup`.

Чтобы прочитать полный текст каждой задачи перед подписью, добавьте `--review`. Выбрать задачи можно флагами `--tasks`, `--only`, `--skip` и `--order`: в них ключи задач через запятую.

## Сначала проба: --dry-run {#dry-run}

Пробный запуск даёт оркестратору — агенту, который планирует, — отсортировать задачи и показывает план в статусе. Ни одна задача не стартует, статусы и комментарии не меняются, код не пишется, очередь остаётся выключенной. Одобрения выбранных задач всё равно подписываются, чтобы оркестратор мог прочитать подписанные тексты.

```sh
tmgr autopilot start --max-teams 2 --dry-run
```

План смотрите командой статуса ниже. Пробный запуск не стартует, пока работает фоновый цикл очереди: сначала выключите очередь.

## Лимиты {#limits}

Лимиты удерживают запуск без присмотра в рамках бюджета.

- `--max-teams N`: Сколько команд работает одновременно
- `--max-hours HOURS`: Сколько часов автопилот запускает новые задачи
- `--max-tasks N`: Сколько задач он запустит
- `--max-cost USD`: Расходы на запуски, оплаченные API-ключом
- `--usage-soft PCT`: С этого процента расхода новые задачи не стартуют
- `--usage-hard PCT`: При этом проценте работающие агенты ставятся на паузу
- `--no-usage-limit`: Запуск без защиты по расходу

Чтобы снять `--max-hours`, `--max-tasks` или `--max-cost`, укажите `none` вместо числа.

### Лимит по времени {#max-hours}

Когда время `--max-hours` истекает, новые задачи не стартуют. Автопилот завершается, как только работающие агенты закончат. Если через 30 минут после лимита агенты всё ещё работают, автопилот прерывает их, пишет в их задачах комментарий `Paused: autopilot time limit reached` и завершается.

### Лимит по деньгам {#max-cost}

`--max-cost` учитывает только запуски, оплаченные API-ключом. Запуски по подписке Claude или Codex в него не входят, и лимит их не останавливает. Если автопилот не может прочитать логи расхода ИИ, он не может проверить лимит и не запускает новые задачи. Разрешить чтение можно командой `tmgr usage consent allow`.

### Лимит тарифа {#usage-guard}

Автопилот следит, сколько лимита тарифа уже израсходовано. Он спрашивает лимиты аккаунта у установленного `claude` или `codex`, поэтому согласие на чтение расхода здесь не нужно; оно важно для лимита по деньгам выше. На мягком проценте автопилот перестаёт запускать задачи, на жёстком ставит работающих агентов на паузу. С `--resume-after-reset yes` он продолжит работу после сброса окна расхода.

Если при запуске реального числа расхода найти не удалось, эти лимиты применить нельзя. Тогда автопилот работает как с лимитом по времени: новые задачи не стартуют после числа часов из `--fallback-hours` — больше 0 и не больше 168. Без флага берётся значение из прошлого запуска с тем же правилом или 8 часов. Если в фоне работает цикл очереди, в этом случае запуск откажется: выключите очередь командой `tmgr queue disable` или передайте `--no-usage-limit`.

## Как идут дела {#status}

```sh
tmgr autopilot status --watch
```

Статус показывает число задач, работающие команды и агентов, лимиты и строку расходов. Без `--watch` он печатает один раз. Если ничего не запущено, вы увидите `Autopilot is not running.`. Когда автопилот закончит, статус перечислит пулл-реквесты.

Последние строки журнала:

```sh
tmgr autopilot log --tail 100
```

## Пауза, продолжение и остановка {#control}

```sh
tmgr autopilot pause
```

Пауза не даёт стартовать новым задачам. Уже работающие агенты доделывают свои задачи.

```sh
tmgr autopilot resume
```

Продолжает работу. Запускайте её сами в обычном терминале: внутри сессии агента команда отклоняется с сообщением `refused inside an agent session`.

```sh
tmgr autopilot stop
```

Остановка прерывает работающих агентов и пишет в их задачах комментарий `Paused: autopilot stopped` со ссылкой на черновой пулл-реквест, если его удалось создать. Затем автопилот завершается и выключает очередь. Если до автопилота очередь работала в фоновом цикле, она вернётся к нему. Чтобы дать работающим агентам доделать задачи, используйте паузу.

Если автопилот не запущен, эти команды ответят `autopilot is not running`.

## Если не запускается {#problems}

- `no queue rule for workspace ...`: у указанного воркспейса нет правила. Добавьте его командой `tmgr queue rules add`.
- `several rules for workspace ...`: у указанного воркспейса больше одного правила. Передайте `--rule NAME`.
- Ошибка 403 со словом `agent-approvals:write`: у вашего входа нет права подписывать одобрения. Войдите заново командой из подсказки. См. [Решение проблем](/docs/ru/cli/troubleshooting).
