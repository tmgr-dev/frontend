`tmgr` — небольшая консольная программа для TMGR. С ней можно работать с задачами, не открывая браузер, и запускать AI-агентов для программирования, например Claude Code и Codex, так, чтобы видеть их работу, останавливать их и откатывать то, что они сделали.

Только начинаете? Пройдите уроки: [1. Установка и вход](/docs/ru/cli/install-and-sign-in) и [2. Задачи из терминала](/docs/ru/cli/tasks-from-the-terminal).

## Установка {#install}

На macOS или Linux:

```sh
curl -fsSL https://tmgr.dev/install.sh | sh
```

sudo не нужен. На Windows используйте WSL2 и выполните ту же команду внутри него.

## Задачи, не выходя из терминала {#tasks}

Одна команда берёт задачу в работу: создаёт git-ветку, переводит задачу в In progress и запускает таймер. Когда закончите, вторая команда останавливает таймер, переводит задачу на ревью и добавляет ссылку на pull request. Переключаться между вкладками не нужно.

```sh
tmgr start TM-123
```

Ещё:

```sh
tmgr status
tmgr board
tmgr today
tmgr switch TM-124
tmgr done
tmgr add "Fix the login redirect"
tmgr task show TM-123
tmgr git install-hooks
tmgr project map
tmgr init zsh
```

`git install-hooks` добавляет ключ задачи в сообщения коммитов. `project map` сообщает `tmgr`, в какой папке лежит код проекта. `init zsh` выводит активную задачу в приглашении командной строки.

## AI-агенты под присмотром {#runner}

Агенты работают в песочнице. С флагом `--worktree` агент получает свою копию проекта и свою ветку, так что два агента никогда не пишут в одни и те же файлы. С флагом `--checkpoints` его работа сохраняется после каждого хода: видно, что изменилось, и это можно откатить. Посмотреть, что агент делает, можно в любой момент.

```sh
tmgr run --agent claude-code --worktree --checkpoints
```

Ещё:

```sh
tmgr attach
tmgr peek
tmgr send
tmgr halt
tmgr resume
tmgr checkpoints diff
tmgr checkpoints restore
tmgr session summary
tmgr session export --page
tmgr runner trust
tmgr runner allow
```

`session export --page` сохраняет сессию страницей в вашем воркспейсе. Для чекпоинтов нужна папка с git. `runner trust` и `runner allow` — экспериментальные команды: они задают, в каких папках и воркспейсах агентам можно запускаться.

## Все вопросы агентов в одном месте {#decisions}

Когда агенту нужно решение, он присылает карточку: вопрос, варианты, свою рекомендацию и изменения, на которые стоит посмотреть. Вы отвечаете один раз в десктопном приложении TMGR, агент получает ответ и продолжает работу. Прошлые ответы можно найти снова, поэтому агенты не спрашивают одно и то же дважды.

```sh
tmgr ask --title "Which database?" --option SQLite --option Postgres --recommended 1 --wait
```

Ещё:

```sh
tmgr decisions answers
tmgr hook install decisions
tmgr mcp
```

Входящие решения (Decisions) работают в десктопном приложении на macOS и Linux. Агенты могут спрашивать и через MCP-инструменты `ask_owner` и `find_answers`.

## Сообщение на телефон, когда агент вас ждёт {#phone}

Можно отойти от компьютера. Пуш придёт, когда агент ждёт ответа или закончил долгую работу. Для срочных случаев есть будильник: он звонит в iOS-приложении TMGR, а если вы не ответили, звонит вам на телефон.

```sh
tmgr alarm "Production is down"
```

Ещё:

```sh
tmgr notify "Build finished"
tmgr hook install claude
tmgr hook install codex
```

Нужны iOS-приложение TMGR и вход в `tmgr` (`tmgr login`). Те же инструменты есть в пакете [@tmgr/notify](https://www.npmjs.com/package/@tmgr/notify) для любого MCP-клиента; он работает с токеном из раздела Настройки → Оповещения агентов.

## Агенты разбирают ваш бэклог {#autopilot}

Направьте автопилот на воркспейс, и он запустит команды агентов на ваши задачи в заданных вами рамках: сколько команд, сколько часов, сколько денег. Если разрешено читать данные о расходе (`tmgr usage consent allow`), он остановится раньше, чем вы упрётесь в лимит тарифа, и может продолжить, когда лимит обновится.

```sh
tmgr autopilot start --max-teams 2 --max-hours 4 --dry-run
```

Ещё:

```sh
tmgr autopilot status
tmgr agents login
tmgr agents sync
```

С `--dry-run` автопилот только строит план и ничего не запускает. `--max-cost` учитывает только запуски, оплаченные по API-ключу. `agents login` и `agents sync` — экспериментальные команды: они управляют входом профиля агента, который используют сессии раннера.

## Сколько стоят AI-инструменты и сколько осталось лимита {#usage}

Расходы по дням, задачам и аккаунтам и запас до лимита видны без страницы биллинга. `tmgr` читает логи расхода Claude Code и Codex на вашем компьютере. Ваши промпты в базу расхода не попадают.

```sh
tmgr usage --week --by task
```

Ещё:

```sh
tmgr usage limits
tmgr usage task TM-123 --tree
tmgr usage statusline install
tmgr time
```

Десктопное приложение спрашивает разрешения, прежде чем читать логи. В терминале команды usage, которые вы запускаете сами, читают их, пока вы не выполните `tmgr usage consent deny`.

## Вместе с десктопным приложением {#desktop}

`tmgr` работает рядом с десктопным приложением TMGR. Решения приходят в приложение, локальные воркспейсы, которые не уходят в облако, доступны и из командной строки, а общие навыки можно подключать к вашим персонам.

```sh
tmgr --ws local:my-notes status
```

Ещё:

```sh
tmgr skills list
tmgr skills attach
```

## Те же инструменты для ваших агентов {#agents}

`tmgr` поддерживает MCP, поэтому Claude Code, Codex, Cursor и другие агенты сами задают вам вопросы, находят ваши прошлые ответы и присылают уведомления. Чтобы они работали и с задачами, подключите ещё и сервер задач TMGR.

```sh
tmgr mcp
```

Ещё:

```sh
tmgr hook install claude
tmgr hook install codex
```

Пошаговая настройка для каждого агента — в [руководстве по AI-агентам](/docs/ru/agents).

## Безопасность {#safety}

- Токен входа хранится в системной связке ключей (а если её нет, в закрытом файле), и `tmgr` никогда его не выводит.
- `tmgr self-update` ставит только релизы с действительной подписью и проверяет их, прежде чем заменить себя.
- Агенты по умолчанию работают в песочнице. Чтобы выйти из неё, нужно явно ввести подтверждение.
- Сервер TMGR никогда не отправляет команды вашим агентам. Вы управляете ими со своего компьютера.
- `tmgr setup terminal` настраивает копирование из `tmgr attach` по SSH. Команда показывает, что изменит, и сначала спрашивает.
