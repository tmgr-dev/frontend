TMGR работает с Telegram, GitHub и Cursor. Каждая интеграция — это модуль, и все три по умолчанию выключены: Telegram bot, GitHub и Cursor agents. Владелец включает их в [Настройки → Модули](/settings/modules), в группах Integrations и AI agents. См. [Справочник модулей](/docs/ru/app/modules).

## Telegram-бот {#telegram}

Через бота можно создавать рутины, задачи и заметки на страницах прямо из Telegram и получать туда уведомления TMGR. Бот отвечает на английском.

### Привязка аккаунта {#telegram-link}

1. Откройте [Настройки → Профиль](/settings?tab=profile). Раздел **Telegram** там есть, пока включён модуль Telegram bot.
2. Нажмите **Подключить Telegram**, затем **Открыть Telegram**.
3. Telegram откроет бота. Нажмите Start. Бот ответит "Telegram account linked to tmgr."

Ссылка одноразовая и действует 30 минут. Если она истекла, нажмите **Подключить Telegram** ещё раз. Когда аккаунт привязан, в разделе написано **Подключено как @имя**. **Отвязать** снимает привязку после подтверждения.

Если этот аккаунт Telegram уже привязан к другому аккаунту TMGR, бот спросит, перенести ли привязку. Ответьте **Yes** или **No**.

Всё, что вы создаёте через бота, попадает в ваше рабочее пространство по умолчанию. Это пространство, владелец которого вы, обычно самое первое. Бот работает, только пока в этом пространстве включён модуль Telegram bot.

### Рутины {#telegram-routines}

- `/add Купить молоко` сразу создаёт рутину. У неё нет даты, и она видна на сегодня, пока вы её не выполните. Добавьте `!high`, `!medium` или `!low`, чтобы задать приоритет.
- Любой другой текст создаёт черновик: бот спрашивает "Create routine: …?" с кнопками **Confirm** и **Cancel**. Черновик без ответа истекает через час.
- Голосовое сообщение превращается в текст и становится таким же черновиком. Размер — до 20 МБ.

### Заметки на страницах {#telegram-notes}

Бот дописывает текст в конец страницы. Для этого в пространстве по умолчанию должен быть включён модуль Pages.

- `/note Идеи Попробовать новый макет` добавит «Попробовать новый макет» на страницу «Идеи».
- Ответьте на текстовое или голосовое сообщение командой `/note Идеи`, чтобы добавить это сообщение.
- Отправьте голосовое с подписью `/note Идеи` или `to Идеи`.
- Перешлите сообщение, в первой строке которого `to Идеи`, а ниже — текст.

Страница ищется по названию, адресу или номеру. Название можно взять в кавычки. Если подходящей страницы нет, бот предложит до 3 похожих кнопками. Каждая заметка добавляется строкой с датой. На странице человека она попадает под заголовок Timeline.

### Задачи {#telegram-tasks}

- `/task Починить страницу входа` создаёт задачу с таким названием.
- Ответьте на любое сообщение командой `/task`, чтобы сделать из него задачу. Сообщение попадёт в описание.

Задача создаётся в пространстве по умолчанию, в статусе по умолчанию и без проекта. Бот отвечает "Task created" со ссылкой.

`/task` работает и в групповом чате. Добавьте бота в группу и ответьте на сообщение командой `/task`. Это может сделать любой участник группы, который привязал свой Telegram, и задача попадёт в его пространство по умолчанию. Группа видит только "Task created.", подробности приходят вам в личный чат с ботом.

`/help` показывает список команд.

### Уведомления в Telegram {#telegram-notifications}

Откройте [Настройки → Уведомления](/settings?tab=notification) и найдите **Уведомления в Telegram**. Включите **Отправлять уведомления в Telegram-бот** и отметьте нужные типы. В Telegram TMGR отправляет такие типы:

- **Статус задачи изменён** и **Новый комментарий** — автору и исполнителям задачи. **Задача назначена** — тем, кого только что назначили. О своих собственных изменениях вы уведомление не получаете.
- **Новая страница**, **Страница обновлена** и **Вас упомянули на странице**.
- **Участник удалён**.

В разделе **Агенты** на той же странице переключатель **Telegram** отправляет вам уведомления, которые AI-агенты шлют с токеном для уведомлений. См. [Уведомления и оповещения от агентов](/docs/ru/app/notifications).

## GitHub {#github}

GitHub App привязывает репозиторий к проекту. Коммиты, ветки и pull request'ы, в которых упомянут ключ задачи, появляются в этой задаче. Нужен модуль GitHub.

### Привязка репозитория {#github-link}

Это может сделать любой участник, в настройках проекта. См. [Проекты](/docs/ru/app/categories#integrations).

1. В разделе **Интеграции** нажмите **Установить GitHub App** рядом с **GitHub**.
2. Когда приложение установлено, выберите репозиторий в **Выберите репозиторий** и нажмите **Подключить репозиторий**.

У проекта может быть один репозиторий. После привязки панель показывает «Подключено к» с названием репозитория и время последней синхронизации.

- **Синхронизировать** заново читает ветки репозитория.
- **Перепривязать задачи** заново проверяет сохранённые коммиты, ветки и pull request'ы и привязывает их к задачам.
- **Отключить** отвязывает репозиторий после подтверждения.

Что нужно знать: первая установка GitHub App сейчас приостановлена, и **Установить GitHub App** показывает ошибку. В рабочих пространствах, где приложение уже установлено, репозитории привязывать можно.

### Активность в Git у задачи {#github-activity}

Укажите ключ задачи, например TM-24, в одном из мест:

- в сообщении коммита;
- в названии новой ветки;
- в заголовке или описании pull request'а.

TMGR берёт из этого текста первый ключ проекта. Ключ — это то, что стоит перед названием задачи, или номер задачи.

В задаче строка **Активность в Git** показывает число событий. Нажмите на неё, чтобы открыть окно **Активность в Git** с ветками, коммитами и pull request'ами. У pull request'а видно, открыт он, влит или закрыт, и его ветки. Если у проекта нет репозитория, задача пишет «Репозиторий GitHub не привязан» и предлагает **Открыть настройки проекта**.

## Агенты Cursor {#cursor}

Агенты Cursor — облачные агенты от Cursor. Их можно запустить из задачи, и они работают с кодом в вашем репозитории GitHub. Для этого нужен модуль Cursor agents, API-ключ Cursor в проекте и репозиторий GitHub, привязанный к тому же проекту.

### Добавить API-ключ {#cursor-key}

1. В настройках проекта, в разделе **Интеграции**, нажмите **Подключить** рядом с **Агент Cursor AI**.
2. Вставьте ключ в поле **API-ключ Cursor**. Его выдают в Cursor Dashboard.
3. Нажмите **Сохранить API-ключ**.

После этого панель пишет **Агент Cursor AI настроен**. TMGR больше никогда не показывает ключ. **Обновить ключ** заменяет его, **Удалить ключ** удаляет. Это может сделать любой участник рабочего пространства.

### Запуск агента {#cursor-run}

1. В задаче с проектом нажмите кнопку с роботом **Запустить в Cursor Agent**. Откроется окно **ИИ-агент Cursor**.
2. В блоке **Запустить нового агента** выберите **Исходная ветка**. Чтобы найти ветку, начните вводить в «Поиск веток…».
3. Нажмите **Запустить Cursor Agent**, чтобы агент поменял код, или **Исследование**, чтобы получить только отчёт.

Агент получает название задачи, описание, проект и комментарии людей. Отдельного промпта нет.

- **Запустить Cursor Agent**: агент работает в новой ветке и открывает pull request. Его просят указать ключ задачи в заголовке pull request'а и в сообщениях коммитов, чтобы они появились в активности Git задачи.
- **Исследование**: агент изучает задачу и публикует отчёт комментарием. Код он не меняет, ветка и pull request не создаются.

**История агентов** показывает агентов задачи со статусом, **Ветка:**, **Сводка:** и **Открыть pull request**. Пока агент работает, окно обновляется само; **Обновить статус** проверяет сразу. **Остановить** останавливает работающего агента. **Активные агенты** вверху страницы или в строке состояния десктопного приложения показывают агентов, которые работают сейчас.

### Дополнительная инструкция {#cursor-follow-up}

Пока агент работает, ему можно дописать инструкции:

- в окне агента, в поле **Отправить дополнительную инструкцию**, затем **Отправить**;
- или написать комментарий и нажать **Отправить в Cursor Agent** в поле комментария.

Текст также сохраняется как ваш комментарий к задаче. Длина — до 5000 символов.

## Способы входа {#sign-in}

На странице входа есть **Google**, **Apple** и **GitHub**, затем Telegram, затем «Или продолжите с email» с email и паролем. В десктопном приложении те же кнопки и кнопка **Telegram**, которая входит через браузер.

- **Telegram** входит в тот аккаунт TMGR, который привязал этот аккаунт Telegram к боту. Если привязанного аккаунта нет, TMGR создаёт новый. Telegram никогда не входит в аккаунт по email.
- **Google**, **Apple** и **GitHub** входят в ваш аккаунт. Если аккаунта с таким email ещё нет, TMGR его создаёт.

### Добавить способ входа к аккаунту {#sign-in-link}

Если у вас уже есть аккаунт и вы впервые входите через провайдера, TMGR должен убедиться, что email ваш:

- Google с адресом Gmail или доменом вашего Google Workspace и Apple с адресом private relay привязываются к аккаунту сразу.
- В остальных случаях, и всегда для GitHub, TMGR присылает письмо со ссылкой для подтверждения. Она действует час. Откройте её, когда вы вошли в свой аккаунт, нажмите **Подтвердить привязку**, затем снова войдите через провайдера.

Если email аккаунта ни разу не подтверждали, вход с этим адресом через провайдера из первого пункта (Google с адресом Gmail или домена Google Workspace, Apple с адресом private relay) забирает аккаунт себе. Старый пароль перестаёт работать, другие способы входа и привязка Telegram удаляются, все сессии завершаются.

Страницы со списком способов входа нет, удалить способ входа тоже нельзя. Если вы зарегистрировались через Google, GitHub или Apple и не задавали пароль, задайте его через «Забыли пароль?» на странице входа.
